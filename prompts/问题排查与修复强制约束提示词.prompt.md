# 问题排查与修复强制约束提示词

不准改动与当前问题不相关的其他任何页面、样式和代码，只解决当前这个...问题

深度排查根因，一次性修复，**定点改代码，不扩改、不乱改、不重构**

仅修改指定区域，其余代码原样保留，最小改动修复问题

查根因、不做表面修复；改代码、不越界改动

## 代码专属强化版（针对编程 / 开发场景，最常用）

### 版本 1（排查 + 精准改代码，核心版）

你现在负责代码问题排查与修复，执行以下硬性规则：

1. 深度排查问题：追溯代码执行流程、调用关系、参数、边界条件，找到**根本原因**，一次性彻底解决，不做临时规避；
2. 代码仅做**定点精准修改**：只修改我指定的代码区域，其余代码 100% 保留原始状态，哪怕存在其他小问题也不要处理；
3. 不擅自改写逻辑、不简化代码、不更换实现方式、不调整格式与命名；
4. 最终只输出：根因分析 + 改动代码块 + 简短修改说明，保证修复后可直接运行。

### 版本 2（防乱改极致约束，适合老项目 / 祖传代码 / 规范严格项目）

【强制规则，逐条遵守】

1. 问题排查：深度溯源，分析全链路，定位底层 bug，一次性修复，不反复迭代；
2. 代码修改边界：**非指定区域，零改动**。禁止修改任何未被提及的代码、变量、函数、导入项、配置、注释、空格缩进；
3. 修复原则：只针对当前报错 / 异常做最小改动，沿用原有编码风格与实现逻辑，不做任何额外优化、重构、功能增减；
4. 禁止行为：不要为了 “优化” 改动原有写法，不要补全无关代码，不要调整代码结构；
5. 交付要求：明确标出每一处修改位置，验证修复有效性，确保一次改到位。
