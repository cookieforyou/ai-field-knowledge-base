## Vibe Coding 必读指南（重要）

将一个灵感通过 **Vibe Coding（氛围编程）** 落地为软件，核心在于**身份的转变**：你不再是“逐行敲代码的砖瓦匠”，而是 **“产品经理 + 架构师 + 验收员”**，而 AI Agent 是你的“高级全栈开发工程师”。

要让 AI 精准 get 到你的意思、减少反复修改、节省 Token 并提升输出质量，你需要建立一套**系统化的工程方法**，而不是单纯依赖“聊天”。以下是 2026 年业界沉淀下来的 Vibe Coding 核心实战指南：

### 一、 动手前的“黄金 30 分钟”：SDD（规格驱动开发）

> **核心法则：Measure twice, cut once（三思而后行）。AI 写错代码往往不是因为它笨，而是因为你没说清。**

不要一上来就对 AI 说“帮我写一个类似小红书的 App”，这会导致灾难性的 Token 浪费和代码混乱。你需要先准备以下“文档”：

#### 1. 编写 `spec.md`（需求规格说明书）

在项目的根目录创建一个 `spec.md` 或 `PRD.md`，用结构化的自然语言写清你的灵感。
*   **包含内容**：产品愿景、目标用户、核心功能列表（按优先级排序）、用户故事（User Story）、非功能性需求（如并发量、响应时间）。
*   **好处**：AI 每次迷茫或跑偏时，你只需要让它 `@spec.md` 重新对齐目标，无需重复输入背景。

#### 2. 配置 `.cursorrules` 或 `CLAUDE.md`（项目宪法）

这是 Vibe Coding **最强大的省 Token 神器**。将你所有的“全局偏好”写进这个文件，AI 每次对话都会自动读取，你再也不用在每次提问时重复废话。
*   **技术栈锁定**：“本项目前端使用 Next.js 14 + TailwindCSS + Shadcn UI，后端使用 Supabase，严禁使用其他框架。”
*   **代码风格**：“使用 TypeScript，优先使用箭头函数，所有变量必须有类型注释，禁止使用 `any`。”
*   **UI/UX 偏好**：“设计风格参考 Stripe，保持极简，主色调为 `#0A0A0A`，使用圆角卡片。”
*   **行为约束**：“修改代码前必须先说明计划；不要删除我的注释；不要生成无用的 README 解释。”

### 二、 提示词工程：如何让需求“一步到位”

> **核心法则：把 Prompt 当作 API 文档来写，消除一切歧义。**

#### 1. 使用“四要素”提示词框架

一个高质量的 Vibe Coding 提示词应该包含：**上下文 (Context) + 意图 (Intent) + 约束 (Constraints) + 验收标准 (Acceptance Criteria)**。

❌ **糟糕的提示词（浪费 Token，修修补补）**：

> “帮我加个登录功能，要好看一点。”

✅ **一步到位的提示词**：

> **[上下文]** 我们目前在做一个 SaaS 仪表盘，使用的是 NextAuth 和 Tailwind。参考 `@spec.md` 中的用户模块。
> **[意图]** 请实现一个邮箱+验证码的登录页面。
> **[约束]** 1. 使用 Shadcn UI 的 Input 和 Button 组件；2. 包含“记住我”选项；3. 错误提示使用 Toast 弹窗，不要阻塞页面；4. 必须做前端表单校验（Zod）。
> **[验收标准]** 输入非法邮箱时按钮置灰；点击发送后按钮显示 Loading 状态并禁用 60 秒。请先给出实现方案，我确认后再写代码。

#### 2. “先计划，后执行”（Plan Mode）

对于稍微复杂的需求，**永远不要让 AI 直接动手写代码**。
*   **话术**：“请不要直接写代码。先阅读 `@folder` 里的现有架构，给出你的实现步骤、需要修改的文件列表以及可能影响的模块。等我 Review 后再执行。”
*   **效果**：这能避免 AI “头痛医头脚痛医脚”，破坏现有架构，同时大幅减少因为方向错误导致的代码回滚和 Token 浪费。

#### 3. 善用视觉参考（Few-Shot Prompting）

AI 的视觉理解能力已经极强。与其用 500 字描述一个 UI 布局，不如直接：
*   扔一张截图：“按照这个网页的布局和配色，用 Tailwind 复刻一个静态页面。”
*   画一个草图/线框图拍照上传：“这是手绘的仪表盘布局，请将其转化为 React 组件。”
*   给一个参考链接：“抓取这个页面的 DOM 结构逻辑，应用到我们的列表页。”

### 三、 上下文与 Token 管理（省钱 & 防变笨）

> **核心法则：上下文窗口是一块会写满的白板，写满了 AI 就会“降智”。**

很多新手在一个对话窗口里聊了三天三夜，最后发现 AI 开始胡言乱语、忘记之前的设定。这是因为**上下文污染**。

#### 1. 及时重置对话（Context Reset）

*   **规则**：每完成一个独立功能（或每 30-45 分钟），**立刻开启一个新的 Chat / Session**。
*   **做法**：在新对话中，只 `@` 相关的几个核心文件，并一句话概括背景（“基于我们刚才提交的 Git 记录，现在继续开发支付模块”）。这能让 AI 始终保持最高智商，并节省海量 Token。

#### 2. 把 Git 当作“存档点”

*   在让 AI 进行大规模重构或尝试不确定的功能前，**必须先 `git commit`**。
*   如果 AI 改崩了，不要试图在对话里让它“改回去”（这会消耗双倍 Token 且容易出错），直接 `git reset --hard`，然后换一种提示词重新来。

#### 3. 保持工作区“干净”

AI Agent 在读取项目时，会把没用的测试文件、废弃的旧代码、甚至 `node_modules` 的某些内容读进上下文，白白消耗 Token。
*   **习惯**：定期删除不用的文件；使用 `.cursorignore` 或 `.aiignore` 屏蔽日志、构建产物和无关目录。

#### 4. 模型分层策略（好钢用在刀刃上）

*   **写架构、定规范、复杂逻辑推理**：使用最顶级的模型（如 Claude Opus / o3），不惜 Token。
*   **写样板代码、调 CSS、写单元测试、简单重构**：使用便宜快速的模型（如 Claude Sonnet / GPT-4o-mini），甚至本地开源模型。

### 四、 避坑指南：提升 Agent 输出质量的秘诀

#### 1. 喂原始报错，不要“人工翻译”

当代码跑不通时，**千万不要自己总结错误**（比如“好像数据库连不上”）。
*   **正确做法**：直接把终端里的 Traceback、浏览器的 Console 报错日志、甚至网络请求的 Payload 原封不动地复制给 AI。AI 对机器语言的理解比你的人工转述精准 100 倍。

#### 2. 提供“示例代码”（Show, Don't Tell）

如果你希望 AI 按照某种特定的模式写代码（比如你们团队特有的数据请求 Hook），不要试图用语言描述，直接打开一个写得好的旧文件：
*   “请**完全模仿** `@useUserAuth.ts` 的代码结构、错误处理方式和命名规范，为我写一个 `@usePaymentData.ts`。”

#### 3. 引入 MCP（模型上下文协议）工具

现在的 AI Agent 不应该只是“盲写代码”。通过配置 MCP，你可以让 AI 拥有“眼睛和手”：
*   **浏览器 MCP**：让 AI 自己打开网页看渲染效果，自己调整 CSS 直到完美。
*   **数据库 MCP**：让 AI 直接查询你的 Supabase/PostgreSQL 数据库结构，写出的 SQL 和 ORM 代码绝对精准。
*   **文档 MCP (如 Context7)**：让 AI 实时拉取最新版本的第三方库官方文档，避免使用已废弃的 API。

#### 4. 隔离“脏活累活”（Sub-agent 模式）

如果你使用的是支持多 Agent 的工具（如 Claude Code 或 Cursor 的特定工作流），把消耗 Token 且不需要全局上下文的“脏活”交给子代理。
*   例如：“生成这 50 个国家的 JSON 测试数据”、“给这个文件夹下的所有函数补充 JSDoc 注释”。让子代理在后台跑，不污染主对话的上下文。

### 💡 总结：Vibe Coding 的高效工作流（SOP）

当你有一个灵感时，请严格按照以下步骤执行：

1.  **Idea 阶段**：自己手写 `spec.md`（梳理逻辑，防止自己都没想清楚）。
2.  **基建阶段**：让 AI 帮你生成项目脚手架，并配置好 `.cursorrules` 和 `.gitignore`。
3.  **拆解阶段**：将 `spec.md` 拆解为 10 个独立的小 Task（如：1. 数据库建表 -> 2. 鉴权接口 -> 3. 登录 UI）。
4.  **执行阶段**：**一个 Task 开一个新对话** -> 给出四要素 Prompt -> 让 AI 先出方案 -> 确认 -> 生成代码 -> 运行测试。
5.  **验收阶段**：Git 提交 -> 开启下一个 Task。

**记住一句话：在 Vibe Coding 时代，你的“品味”、“逻辑清晰度”和“拆解问题的能力”，就是你编写出的最强大的代码。**
