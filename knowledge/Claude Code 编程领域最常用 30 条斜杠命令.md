Claude Code 新版本进一步完善了 Agent 自治能力、多智能体协作以及内置 Skills 技能树，其命令体系已经分为 **内置控制命令** 和 **内置高级技能（Skills）**。

以下是精心整理的**编程领域最重要、最常用的 30 条斜杠命令**。为了便于查阅，将其分为六大核心开发场景，并配备了详细说明与实战用法。

---

### 一、 🎯 目标自治与自动化编排 (Agent 核心能力)

这是 Claude Code v2.1.x 版本最强大的特性，让 AI 从“问答工具”变成“自动干活的员工”。

| 命令 | 详细说明 | 实战用法示例 |
| :--- | :--- | :--- |
| **`/goal`** | **目标驱动模式**。设定一个“可验证的完成条件”，AI 会自主规划并持续多轮执行，直到条件满足或触发停止机制，中途无需人工干预。 | `/goal 修复所有 ESLint 报错，并确保 npm test 退出码为 0` |
| **`/loop`** | **定时/循环任务**。按时间间隔或特定条件循环执行某个指令，适合后台监控、定时重构或持续集成检查。 | `/loop 30m /review --branch main` (每30分钟审查一次 main 分支) |
| **`/batch`** | **批处理模式**。将一个大任务拆解为多个独立子任务，并行或串行执行，适合批量修改文件或生成测试用例。 | `/batch 为 src/services/ 下的所有 TS 文件补充 JSDoc 注释` |
| **`/agents`** | **多智能体管理**。列出、调用或配置专用的子代理（SubAgents），将特定领域的任务委派给专业 Agent。 | `/agents security-audit 检查 src/auth/ 目录的越权漏洞` |

### 二、 🧠 项目记忆与上下文管理 (防 Token 浪费)

编程时上下文极易超限，这组命令是控制 Token 消耗和保持 AI 智商的关键。

| 命令 | 详细说明 | 实战用法示例 |
| :--- | :--- | :--- |
| **`/init`** | **项目初始化**。扫描代码库结构、依赖和技术栈，自动生成 `CLAUDE.md` 项目记忆文件，让 AI 瞬间懂你的项目。 | `/init` (首次接手新项目或开源库时必敲) |
| **`/memory`** | **记忆管理**。打开编辑器查看或修改 `CLAUDE.md`，手动注入团队规范、业务黑话或架构约束。 | `/memory add "所有 API 返回必须包含 trace_id 字段"` |
| **`/compact`** | **上下文压缩**。将冗长的对话历史压缩为结构化摘要，大幅节省 Token，同时保留核心逻辑。支持指定保留重点。 | `/compact 保留数据库迁移脚本的讨论和未解决的 Bug` |
| **`/clear`** | **清空重置**。彻底清空当前对话历史。当 AI 陷入死循环或任务完全切换时使用，防止旧上下文干扰。 | `/clear` (换下一个独立需求时使用) |
| **`/btw`** | **侧边提问**。临时问一个无关问题（如拼写、语法、快速查阅），**答案不计入主上下文**，防止污染当前开发任务。 | `/btw Redis 的 SETNX 和 SET EX 有什么区别？` |
| **`/add-dir`** | **扩展目录**。将当前工作区之外的目录加入 AI 的读取范围，适合 Monorepo 或跨微服务引用代码。 | `/add-dir ../payment-service/src` |

### 三、 🔍 代码审查与重构 (内置高级 Skills)

Claude Code 内置了强大的审查技能树，比单纯用自然语言要求“帮我 review”更深度、更结构化。

| 命令 | 详细说明 | 实战用法示例 |
| :--- | :--- | :--- |
| **`/review`** | **深度代码审查**。对当前 Git 暂存区或指定分支的代码进行结构化审查，检查逻辑缺陷、边界条件和性能瓶颈。 | `/review --branch feature/login` |
| **`/simplify`** | **代码简化与重构**。专门用于降低代码复杂度、消除重复逻辑、提取公共函数，提升代码可读性。 | `/simplify src/utils/dateParser.ts 降低圈复杂度` |
| **`/security-review`** | **安全漏洞扫描**。聚焦 SQL 注入、XSS、越权访问、硬编码密钥等安全隐患进行专项审查。 | `/security-review src/api/` |
| **`/pr-comments`** | **处理 PR 评审意见**。自动读取 GitHub/GitLab 上的 PR 评论，并逐条分析、给出修改方案或直接修复。 | `/pr-comments 1024` (处理编号为 1024 的 PR 评论) |

### 四、 🛠️ 代码变更与版本控制 (防翻车机制)

AI 改错代码是常态，这组命令是你的“后悔药”和“透视镜”。

| 命令 | 详细说明 | 实战用法示例 |
| :--- | :--- | :--- |
| **`/diff`** | **交互式变更查看**。以 Git Diff 风格在终端高亮展示本次会话中 AI 对所有文件的增删改，支持逐行 Accept/Reject。 | `/diff` (在 AI 完成一大波修改后，提交前必查) |
| **`/undo`** | **撤销修改**。回滚 AI 上一次对文件系统做出的修改。如果 AI 改坏了代码，可连续执行多次撤销。 | `/undo` (AI 把代码改崩了，立刻撤销) |
| **`/commit`** | **智能提交**。自动分析当前 `git status` 和 `diff`，生成符合 Conventional Commits 规范的 commit message 并执行提交。 | `/commit` |

### 五、 ⚙️ 模型、诊断与系统控制

用于调整 AI 的“大脑”、排查环境问题以及管理外部工具链。

| 命令 | 详细说明 | 实战用法示例 |
| :--- | :--- | :--- |
| **`/model`** | **切换模型与思考力度**。在 Opus/Sonnet/Haiku 之间切换，或调整 Extended Thinking（深度思考）的级别。 | `/model opus --thinking=high` (处理极复杂的架构设计) |
| **`/cost`** | **成本监控**。实时显示当前会话的 Token 消耗量、API 调用次数及预估美元成本，防止账单爆炸。 | `/cost` |
| **`/mcp`** | **MCP 服务器管理**。管理 Model Context Protocol 连接，让 AI 能够调用外部数据库、Jira、Figma 等第三方工具。 | `/mcp connect postgres://localhost:5432/dev_db` |
| **`/doctor`** | **环境健康诊断**。排查 Claude Code 无法运行、网络超时、权限报错等问题，自动检测 Node 版本和 API Key 状态。 | `/doctor` (遇到玄学报错时先跑一遍) |
| **`/debug`** | **自我调试**。当 Claude Code 自身的行为出现异常（如工具调用失败、死循环）时，让 AI 启动内部诊断流程。 | `/debug` |
| **`/permissions`** | **权限白名单/黑名单**。精细控制 AI 可以读写哪些目录、可以免确认执行哪些 Shell 命令（如 `npm run`）。 | `/permissions allow "npm test, git *"` |

### 六、 🧩 状态、配置与辅助

日常开发的辅助命令，提升终端交互体验。

| 命令 | 详细说明 | 实战用法示例 |
| :--- | :--- | :--- |
| **`/status`** | **会话状态面板**。显示当前所在的 Git 分支、关联的 Agent、已加载的 MCP 服务和当前使用的模型。 | `/status` |
| **`/config`** | **全局/项目配置**。查看或修改 Claude Code 的底层配置（如默认模型、自动压缩阈值、主题颜色）。 | `/config set autoCompactThreshold 80` |
| **`/vim`** | **Vim 模式切换**。为习惯 Vim 键位的开发者开启终端 Vim 编辑模式，提升长 Prompt 的编辑效率。 | `/vim` |
| **`/help`** | **动态帮助手册**。列出当前环境下所有可用的内置命令和自定义 Skills，支持关键词过滤。 | `/help review` |
| **`/exit`** | **安全退出**。正常结束会话并保存历史记录（比直接按 `Ctrl+C` 或关终端更安全，不易损坏本地状态）。 | `/exit` |

### 💡 Claude Code 斜杠命令高阶实战建议

1. **组合拳工作流**：
  - 接手新项目时：`/init` ➔ `/memory` (补充团队规范) ➔ `/review` (了解历史技术债)。
  - 开发新需求时：`/goal` (设定测试通过的终态) ➔ `/diff` (审查 AI 的改动) ➔ `/commit` (提交)。
2. **自定义 Skills (技能树扩展)**：
  - 除了上述 30 个内置命令，v2.1.x 极度鼓励**自定义命令**。您可以在项目根目录创建 `.claude/commands/fix-test.md`，写入修复测试的 Prompt 模板。之后，您和团队就可以直接在终端输入 `/project:fix-test` 来触发专属工作流。
3. **防止 `/goal` 破产**：
  - 使用 `/goal` 时，**务必在 Prompt 中加上物理边界和熔断机制**。例如：`/goal 修复登录接口的并发问题，要求测试通过。注意：仅允许修改 src/auth/ 目录，如果尝试 3 次仍未通过测试，请立刻停止并输出失败原因。`
