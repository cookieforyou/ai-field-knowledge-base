| 阶段 | 主题 | 目标 | 预计时间 |

## 📌 阶段①：用起来——成为 AI 高效用户（1~2 周）

> **核心目标**：不再只是"偶尔问问 ChatGPT"，而是把 AI 融入你每天的工作场景。

### 🎯 具体行动

| 序号 | 做什么 | 具体说明 |
|:---:|--------|----------|
| 1 | **注册并体验主流 AI 对话产品** | 至少各用 3 天：ChatGPT（GPT-4o）、Claude（Sonnet/Opus）、Gemini、Kimi（国内）、通义千问、豆包。感受它们各自的强项 |
| 2 | **列出你日常工作中的 10 个高频任务** | 比如：写邮件、整理会议纪要、读论文/报告、写方案、做 PPT 大纲、数据分析、翻译、代码调试、信息检索、头脑风暴 |
| 3 | **逐一尝试用 AI 完成这 10 个任务** | 每个任务至少用 AI 做 3 次，体会哪种提问方式效果最好 |
| 4 | **建立你的「AI 使用日志」** | 用一个笔记文件记录：今天让 AI 做了什么 → 效果如何 → 怎么改进 |

### 🛠️ 推荐工具清单

| 用途 | 推荐工具 | 说明 |
|------|----------|------|
| 通用对话 | ChatGPT、Claude、Kimi | 写作/分析/创意用 Claude；联网搜索用 ChatGPT/Kimi |
| 文档处理 | Kimi（长文档）、ChatGPT（文件上传） | Kimi 支持 200 万字上下文，适合读长文档 |
| 图片理解 | GPT-4o、Claude | 上传截图让 AI 帮你分析 |
| 语音 | ChatGPT 语音模式 | 通勤时用语音对话，当随身顾问 |

## 📌 阶段②：问得好——掌握 Prompt Engineering（2~3 周）

> **核心目标**：同样的 AI，你问出来的东西比别人质量高 3 倍。

### 🎯 具体行动

#### 第一步：掌握 Prompt 万能公式（第 1 天）

```
[角色] + [背景] + [任务] + [要求/约束] + [输出格式]
```

**反面例子**：
> "帮我写个方案"

**正面例子**：
> "你是一位资深的产品经理（角色），我们公司要推出一款面向中小企业的 AI 客服 SaaS 产品（背景），请帮我撰写一份产品立项方案（任务），要求包含市场分析、竞品对比、核心功能设计、商业模式和风险评估（要求），用 Markdown 格式输出，每个章节不少于 500 字（格式）"

#### 第二步：学习 10 个核心 Prompt 技巧（第 1~2 周）

| 技巧 | 说明 | 示例 |
|------|------|------|
| **角色设定** | 给 AI 一个专家身份 | "你是一位有 20 年经验的财务分析师" |
| **Few-shot 示例** | 给 1~3 个示例让 AI 模仿 | "请按以下格式输出：[示例1][示例2]，现在请处理这个：..." |
| **Chain of Thought (CoT)** | 要求 AI 逐步推理 | "请一步一步思考这个问题，先分析原因，再给出建议" |
| **结构化输出** | 指定输出格式 | "请用 JSON / 表格 / 分点列表 输出" |
| **拆解任务** | 复杂任务分步做 | "第一步：先列大纲等我确认；第二步：再逐章展开" |
| **设定约束** | 明确不要什么 | "不要使用专业术语，面向非技术人员写作" |
| **自我审视** | 让 AI 检查自己 | "请检查你上面的回答是否有逻辑漏洞，并修正" |
| **对比分析** | 让 AI 做比较 | "请从成本、效率、风险三个维度对比 A 和 B 方案" |
| **迭代优化** | 多轮追问改进 | "这个版本不够好，请在以下方面改进：1... 2... 3..." |
| **元提示** | 让 AI 帮你写 Prompt | "我想让 AI 帮我做 X，请帮我写一个最优的 prompt" |

#### 第三步：学习 Context Engineering（第 2~3 周）

2026 年的共识：**从 Prompt Engineering → Context Engineering**，不只是写好提示词，更要设计好 AI 的「工作环境」：

| 技巧 | 说明 |
|------|------|
| **System Prompt 设计** | 为 AI 设定持久人设和规则（如 Claude 的 Projects、GPT 的 Custom Instructions） |
| **上下文管理** | 知道何时开新对话、何时延续对话，保持 AI 的"记忆"清晰 |
| **知识库挂载** | 给 AI 提供参考文档/资料，让它基于你的真实数据回答 |
| **工作流编排** | 把一个复杂任务拆成多个 AI 步骤串联执行 |

### 📚 推荐学习资源

| 资源 | 类型 | 链接/说明 |
|------|------|-----------|
| Google《Prompt Engineering》白皮书 | 文档 | 搜索"Google Prompt Engineering whitepaper"，65 页系统教程 |
| Anthropic 官方 Prompt 最佳实践 | 文档 | claude.com/blog/best-practices-for-prompt-engineering |
| DeepLearning.AI 短课 | 视频 | "ChatGPT Prompt Engineering for Developers"（免费） |
| OpenAI 官方 Prompt 指南 | 文档 | platform.openai.com/docs/guides/prompt-engineering |

### ✅ 阶段验收标准
- [ ] 你能用万能公式写出结构清晰的 Prompt，一次成功率 > 70%
- [ ] 你会主动使用 CoT、Few-shot、角色设定等技巧
- [ ] 同事/朋友会问你"你怎么让 AI 写出这么好的东西"

## 📌 阶段③：连得通——用 AI 工具链打通工作流（3~4 周）

> **核心目标**：AI 不再只是"聊天窗口"，而是嵌入你工作流的自动化引擎。

### 🎯 具体行动

#### 第一步：掌握 AI 编程/写作助手（第 1~2 周）

即使你不是程序员，这些工具也能极大提效：

| 工具 | 适用场景 | 上手难度 |
|------|----------|:---:|
| **Cursor** | AI 代码编辑器，用自然语言写/改代码 | ⭐⭐ |
| **Claude Code** | 终端 AI 编程助手，处理大规模重构 | ⭐⭐⭐ |
| **GitHub Copilot** | VS Code 内 AI 代码补全 | ⭐ |
| **Windsurf / Trae** | 替代 Cursor 的 AI IDE | ⭐⭐ |
| **Notion AI / 飞书智能伙伴** | 文档写作、知识管理 AI 化 | ⭐ |

#### 第二步：了解并使用 MCP 协议（第 2~3 周）

**MCP（Model Context Protocol）是 2026 年 AI 工具最重要的基础设施**，被称为"AI 时代的 HTTP"。

**一句话理解**：MCP 让 AI 不再只是"聊天"，而是能真正操作你的工具和数据。

**你可以做的事**：
- 在 Claude Desktop 中配置 MCP Server，让 AI 直接读取你的本地文件、数据库
- 在 Cursor 中通过 MCP 连接 GitHub、Jira 等开发工具
- 让 AI 直接查询你的 Notion/飞书文档

**入门步骤**：
1. 下载 Claude Desktop
2. 配置一个简单的 MCP Server（如文件系统、GitHub）
3. 尝试让 AI 通过 MCP 完成一个真实任务

#### 第三步：用自动化工具串联 AI（第 3~4 周）

| 工具 | 说明 |
|------|------|
| **n8n** | 开源自动化工具，可视化编排 AI 工作流 |
| **Dify** | 开源 AI 应用开发平台，可视化搭建 Agent |
| **Coze（扣子）** | 字节跳动的 AI Bot 平台，低代码搭建 Agent |
| **Zapier + AI** | 连接各种 SaaS 工具 + AI 自动化 |

**实战项目建议**：
- 搭一个"每日资讯汇总 Agent"：自动抓取 RSS/网页 → AI 总结 → 推送到飞书/微信
- 搭一个"会议录音 → 纪要生成 Agent"：录音转文字 → AI 提取要点和 TODO → 自动发邮件

### ✅ 阶段验收标准
- [ ] 你至少配置了 1 个 MCP Server 并成功使用
- [ ] 你搭建了至少 1 个自动化 AI 工作流
- [ ] 你的某项日常重复工作已经被 AI 自动化替代

## 📌 阶段④：建得起——入门 Agent 开发（4~6 周）

> **核心目标**：理解 AI Agent 的核心架构，能自己搭建简单的 Agent。

### 🎯 具体行动

#### 第一步：理解 Agent 核心概念（第 1 周）

**AI Agent = 大脑（LLM）+ 规划（Planning）+ 记忆（Memory）+ 工具调用（Tool Use）**

| 组件 | 类比 | 说明 |
|------|------|------|
| **LLM 大脑** | 人的大脑 | 负责理解、推理、决策 |
| **Planning** | 工作计划 | 把复杂任务拆解成子步骤 |
| **Memory** | 笔记本 | 短期记忆（对话上下文）+ 长期记忆（向量数据库） |
| **Tool Use** | 手和脚 | 调用 API、搜索引擎、数据库、代码执行器 |
| **Function Calling** | 接口协议 | LLM 决定何时调用什么工具，传什么参数 |

**重要原则**：先搞懂底层机制，再学框架。不要一上来就学 LangChain，否则出了问题你不知道怎么排查。

#### 第二步：学习 Function Calling / Tool Use（第 1~2 周）

这是 Agent 最核心的能力。

**实操**：
1. 用 OpenAI API 实现一个最简单的 Function Calling（让 AI 调用天气 API）
2. 用 Claude 的 Tool Use 实现同样的功能
3. 理解 JSON Schema 如何定义工具描述
4. 理解模型如何决定"调用工具 vs 直接回答"

#### 第三步：学习 RAG（检索增强生成）（第 2~4 周）

**RAG = 让 AI 基于你的私有数据回答问题**，是实用性最强的 Agent 技术。

**学习步骤**：

| 步骤 | 内容 | 工具 |
|:---:|------|------|
| 1 | 理解 Embedding（文本向量化） | OpenAI Embeddings、BGE |
| 2 | 学习向量数据库 | ChromaDB（最简单）、FAISS、Milvus |
| 3 | 实现基础 RAG 流程 | 文档 → 切片 → 向量化 → 存储 → 检索 → 生成 |
| 4 | 优化 RAG 效果 | Chunk 策略、Reranker、混合检索 |

**推荐框架**：
- **LangChain**：最主流的 LLM 应用开发框架
- **LlamaIndex**：专注于 RAG 的框架
- **Dify**：可视化搭建 RAG 应用

#### 第四步：搭建你的第一个 Agent（第 4~6 周）

**实战项目建议**：
- 🤖 **个人知识库 Agent**：上传你的笔记/文档，AI 基于你的知识回答问题
- 🤖 **智能客服 Agent**：基于产品文档自动回答用户问题
- 🤖 **数据分析 Agent**：上传 CSV/Excel，用自然语言做数据分析

### 📚 推荐学习资源

| 资源 | 说明 |
|------|------|
| Hugging Face AI Agents Course | 免费，最火的 Agent 入门课 |
| DeepLearning.AI LangGraph 短课 | 免费，学习 Agent 状态图编排 |
| LangChain 官方文档 + Cookbook | 最全面的 Agent 开发参考 |
| 吴恩达《AI Agents in LangGraph》 | 短课，2 小时入门 |

### ✅ 阶段验收标准
- [ ] 你能独立实现一个带 Tool Use 的 Agent
- [ ] 你搭建了一个可用的 RAG 应用
- [ ] 你能解释 Agent 的 ReAct 循环（推理→行动→观察→再推理）

## 📌 阶段⑤：玩得深——进阶 RAG + 多 Agent 系统（6~8 周）

> **核心目标**：构建复杂的、可落地的 AI 应用。

### 🎯 具体行动

| 序号 | 学习主题 | 具体内容 |
|:---:|----------|----------|
| 1 | **高级 RAG** | 多路召回、Reranker（Cohere/BGE-Reranker）、Parent Document Retriever、Self-Querying |
| 2 | **Agent 记忆系统** | 短期记忆（对话缓冲）→ 长期记忆（向量存储）→ 工作记忆（Scratchpad） |
| 3 | **LangGraph 状态图** | 用图结构编排 Agent 流程：条件分支、循环、人工介入节点 |
| 4 | **多 Agent 协作** | 用 LangGraph / CrewAI / AutoGen 搭建多 Agent 系统，各 Agent 分工协作 |
| 5 | **评估与优化** | 学会评估 Agent 效果：准确率、幻觉率、工具调用成功率、端到端延迟 |
| 6 | **部署上线** | 用 FastAPI/Streamlit 将 Agent 部署为可访问的服务 |

### 🚀 进阶实战项目

| 项目 | 描述 | 技术栈 |
|------|------|--------|
| **研究报告 Agent** | 给一个主题 → 自动搜索 → 阅读多篇资料 → 生成带引用的研究报告 | LangGraph + Tavily + RAG |
| **代码审查 Agent** | 连接 GitHub → 分析 PR 代码变更 → 生成审查意见 | MCP + GitHub API + Claude |
| **多 Agent 辩论系统** | 多个 Agent 扮演不同角色，对一个问题进行辩论并达成共识 | CrewAI / AutoGen |
| **企业知识库** | 接入公司文档/Wiki，支持多轮对话、权限控制、使用统计 | RAG + FastAPI + 前端 |

### ✅ 阶段验收标准
- [ ] 你能用 LangGraph 构建带条件分支和循环的 Agent 工作流
- [ ] 你搭建了一个多 Agent 协作系统
- [ ] 你有至少一个可以展示给别人的完整 AI 应用

## 💡 给你的 3 条最重要的建议

1. **不要跳过阶段①②直接学框架**——很多人一上来就学 LangChain，结果连 Prompt 都写不好，搭出来的 Agent 效果很差却不知道问题在哪。

2. **边学边用，以用带学**——每个阶段都围绕你**真实的工作场景**做项目，不要只跟教程的 toy example。解决一个真实问题的收获 > 看 10 篇教程。

3. **2026 年的核心趋势是 Context Engineering**——不只是写好 Prompt，而是设计好 AI 的整个运行环境（System Prompt + 知识库 + 工具链 + 工作流）。把精力放在"如何给 AI 提供最好的上下文"上。
